# 本机电机与光谱仪控制台

[项目总览](../README.md) · [机械参数与 Thonny 调试](motor.md) · [测试说明](../tests/README.md)

控制台运行在当前电脑，通过 USB 连接 ESP32，再经 RS485 独立控制三台电机。
所有页面位置与距离统一使用 **mm**。速度单位为 **rpm**，同时显示按导程换算的 mm/s。

## 独立服务与启动入口（2026-11-13）

| 设备 | 启动脚本 | 默认地址 | 前台服务模块 | 独立依赖 |
|---|---|---|---|---|
| 三轴电机 | `./start-control.sh` | `http://127.0.0.1:8765/` | `webcontrol.server` | `webcontrol/requirements-motor.txt` |
| USB 光谱仪 | `./start-spectrometer.sh` | `http://127.0.0.1:8766/` | `webcontrol.spectrometer_server` | `webcontrol/requirements-spectrometer.txt` |

两个脚本在仓库根目录运行，各自启动后台进程。重复执行只复用同设备、同模拟模式的服务；端口上若仍是旧版合并服务，会明确报错。先停止任务、结束记录并断开设备，再退出旧服务，或指定 `--port` 使用其他端口。依赖可分别安装，也可安装 `webcontrol/requirements.txt` 一次准备两者。

电机服务只公开电机 API，光谱仪服务只公开光谱 API；页面只加载自己的控制脚本。两端均保留本机 Host/Origin 与独立页面令牌校验。启动光谱仪不会创建电机控制器、申请电机控制权或打开串口。一个服务退出不结束另一个服务。

两个脚本均支持 `--demo --no-browser`。前台调试可以运行：

```bash
.venv/bin/python -m webcontrol.server --demo --no-browser --port 8875
.venv/bin/python -m webcontrol.spectrometer_server --demo --no-browser --port 8876
```

分别在两个终端执行，使用各自的 `Ctrl+C` 退出。后台日志和 PID 按端口保存在 `webcontrol/runtime/server-<端口>.log` 与 `.pid`。光谱仪断开前应结束记录；关闭浏览器只关闭页面，采集仍可能在后台继续。

以下三轴操作说明适用于电机页面；光谱仪说明见[独立光谱页面](#usb-spectrometer-web)。

## 停止与急停恢复（版本9，2026-11-11）

日常暂停请使用“停止”：发送刹车、确认静止、清除刹车并再次检查位置；通过后保留编码器基准及保存位置，可直接提交新的定位或注射任务，不会自动继续旧任务。停止未确认、通信异常或控制权超时仍清除基准并锁定。

“急停三轴”仍首先广播刹车和失能、取消任务并持久锁存。过去解除急停只解除网页锁存，未恢复驱动器失能，因此可能出现屏幕“异常”且不接受运动。现在勾选已停机、排障并允许恢复驱动力，点击“恢复驱动并解除急停”：重连后读取三轴状态，确认静止，再清除刹车/失能并明确使能，验证状态和编码器，全部通过才解除锁存。故障、失去控制权、停止请求或编码器变化会使恢复失败并重新失能。恢复不发送速度或位移指令，但重新使能可能产生保持力；操作前应确认设备可恢复驱动力。

若没有网页急停锁存、但驱动器显示异常，可在连接后使用设置面板“恢复驱动状态”，同样需要确认。成功后核对当前位置、建立基准，再提交新任务。不可恢复的过载、堵转、欠压或通信故障仍需先排除，恢复按钮不能替代排障。

本次实机只读检查：ID1运行状态8、未堵转、已失能；ID2/3状态1、未堵转、已使能。公开手册只定义运行状态0–5，无法确认8的准确含义，当前恢复流程会拒绝该状态；没有猜测为普通失能后放行，也没有执行真实使能或运动。需取得该驱动器版本的状态定义后继续验证恢复。正常停止流程的基准保留与正常断开修复已经部署。

正常断开/服务退出改用确认停机的退出指令，避免原来每次断开都触发急停失能；退出未确认时仍回退到急停。以下早期版本记录中的“小段停止”“每次停止重新标定”和旧解除流程，以本节及连续运动章节为准。

## 启动与退出

在 `~/Work/enzyflow` 双击 **`启动三轴控制台.desktop`**，或在终端执行：

```bash
cd ~/Work/enzyflow
./start-control.sh
```

默认地址是 **http://127.0.0.1:8765/**。服务只监听本机，不需要外网、Node 或前端构建。
启动器优先使用项目 `.venv/bin/python`，本机已安装独立环境与 `pyserial 3.5`。
**日常网页控制不需要启动 Thonny，也不依赖 Thonny 后端。**
操作顺序为运行脚本、自动打开浏览器、插入 USB、自动识别 ESP32，然后确认当前位置。
重复启动会打开同一服务，不会启动第二个设备控制者。

如果 Thonny 已打开并占用串口，请先选择“运行 → 断开”。
`./start-control.sh --handoff-thonny` 是可选的旧会话交接工具，不是日常运行依赖。
网页与 Thonny 不可同时占用同一个 USB 串口。

页面取得控制权后自动尝试连接 ESP32；默认优先选择匹配的 `/dev/ttyUSB0`；该端口缺席时，仅在恰有一台匹配设备时自动选取。匹配原生 Espressif USB 或当前 `1A86:7523` 转串口；仍需通过 MicroPython 与网页协议握手。
连接本身不会移动电机。板端 `main.py` 仍启动 AS7341，网页连接时会中断该采集程序，
启动 `enzyflow.motor_web` 电机服务；本版不同时运行两种模式。

操作结束可点击“停止”，等待静止确认与位置保存；需要交回 Thonny 时再点击
“断开连接”，然后在 Thonny 中按 `Ctrl+F2` 重连。关闭网页会请求取消并锁定，后台服务
可能继续运行；控制页心跳中断也会取消剩余动作，不能把关闭页面当作立即急停。

## 每次连接后建立基准

1. 核对电机实物标签。当前已确认长轴为 **ID1**，短轴 A/B 为 **ID2/ID3**。
   在“设备与标定”选择长轴，勾选实物确认，再点击“确认对应关系”。查询机号不能自动识别丝杆长短。
2. 用尺逐轴测量滑块距相同机械零点、相同滑块边缘的实际坐标，填入对应轴的 **mm** 输入框。
   不要把历史记录、上次目标或其他轴的读数作为当前值。
3. 核对本机已标定的 **反转前进（−1）、4 mm/圈**，勾选确认并点击“建立基准”。
   等待稳定编码器反馈后，该轴才会显示本次位置。

页面在首次运行、重连、异常或锁定后均不会自动恢复旧坐标。断电、复位、手动移动、换线
或实物对应变化后，重新确认并尺量。重新确认长短轴对应关系会清除已有基准。

| 轴 | 机号 | 机械有效范围 | 普通调节的安全目标范围 |
|---|---:|---:|---:|
| 长轴 | 1 | 20–320 mm | **30–310 mm** |
| 短轴 A | 2 | 20–220 mm | **30–210 mm** |
| 短轴 B | 3 | 20–220 mm | **30–210 mm** |

两端各预留 **10 mm（1 cm）**。尺量 **20 mm** 虽在机械有效范围内，却在普通调节的
安全区外：页面允许记录实测基准，但显示“安全区外”，禁用普通移动，仍可重新测量标定。
请使用下述“向内恢复”；不要通过改填坐标、长短轴或导程绕过保护。

## 多轴同时启动与安全区外恢复（2026-11-10）

**多轴并行：** 各轴标定并进入安全区后，分别填写目标和速度，勾选各卡片的“参与同时启动”，点击“同时启动所选轴”。可选2–3轴；程序先验证全部目标，再以每轴最多1mm的小段并行推进。RS485逐台发送指令，起步有小幅时间差，并非硬件同步轨迹控制；各段等待所选轴反馈后再继续，因此不同速度不保证同时到达终点。

**向内恢复：** 对仍在机械有效范围内、但位于10mm安全余量区的轴，先填写真实尺量位置建立基准。卡片显示恢复区域；确认向内方向和可用空间后，每点击一次，以6rpm朝安全区移动最多0.5mm。临近安全区时自动缩短步长，进入后恢复按钮禁用。两端均支持，禁止向外恢复、越过机械边界或与其他运动并发。无需用手推动丝杆，也不能填写虚假坐标解锁。

停止会取消所有轴的后续段；已发送的小段仍可能完成。重新连接、异常或锁定后仍需重新标定，不续跑旧任务。

部署前备份：`backups/before_parallel_recovery_20261110_143944/`。145项固件测试、36项电脑端测试、模拟HTTP流程和板端假总线验证通过；真实USB握手与状态查询通过。**新增并行/恢复尚未实机运动验收，浏览器实际点击未验收。**

## 双注射器恒速推进（2026-11-10）

用户确认使用两个短轴、注射器内径19.22mm，无压力传感器。短轴A、B可分别设置速率，默认**每支1mL/min，两支合计2mL/min**。1mL/min为1倍，例如A=0.5、B=2分别对应0.5倍和2倍，总计2.5mL/min。

截面积 `π × (19.22/2)² = 290.132679 mm²`；1mL/min推进速度 `1000 / 290.132679 = 3.446699 mm/min`。4mm/圈导程对应 **0.861675rpm**。此模式使用驱动器的小数转速速度指令持续运行，不再每1mm停下来；常规定位仍保留原有3–30rpm限制。

操作步骤：

1. 刷新页面，重新确认机号并尺量标定两个短轴；它们必须位于普通安全区内。
2. 在“双注射器恒速推进”中，分别填写注射速率（mL/min）、选择推动注射器的实际方向，填写推杆当前**剩余可推距离（mm）**。该距离是注射器推杆至行程尽头的距离，不是丝杆总长，也不是mL数。
3. 勾选内径、各自速率、方向和行程确认，点击“按A、B设定速率开始推进”。长轴不参与。
4. 顶部按钮变为“停止注射”。任一注射器到达本次设定终点时也会停止两轴；再次启动前请重新核对当前位置和推杆剩余行程。停止未确认时须重新尺量标定。

终点取“注射器剩余行程减1mm”与“该方向丝杆安全区剩余距离减0.5mm”中较小者。板端每约100ms采样编码器，检查方向、速度偏差、未选择轴漂移和行程；主机每约300ms续约，板端1500ms未收到有效续约即请求停止。网页心跳超时先由主机停止；USB读取半包或等待输入不会暂停板端监督。正常停机对两轴发送刹车，先检查静止，再解除刹车并二次检查；任一阶段异常会广播失能。停机无法确认时界面报错并禁止再次启动。

短轴 A、B 各自可以勾选「按距离分段调速」，默认关闭。每行填写一段距离和对应速率，例如 `2, 0.5` 表示以 0.5 mL/min 推进 2 mm。每轴可设 1–12 段，每段至少 0.5 mm，总距离不得超过安全行程。启用任一轴的分段模式后，各轴分别在自己的终点停止，未启用的轴按固定速率推进至安全行程终点。两支仍须填写实测剩余行程和方向。

这是**恒速推进，不是恒压控制**；显示体积是依据内径和编码器计算的估计值。实际低速稳定性与实际流量需收集称量校验。软件不能在控制器断电/复位、RS485故障或电机驱动器故障时保证停止；此类情况需切断电机电源，不应无人监护运行。

协议依据：[制造商资料入口](https://www.openedv.com/docs/industry/MotorDriver/PD42S1.html)及[制造商用户手册镜像](https://studylib.net/doc/28979752/pd42s1%E6%AD%A5..v1-5736)第4.4.2、4.4.12、4.4.13节（速度F1、刹车FC、解除状态FB）。F1转速为大端IEEE754 float，注射路径另限0.1–2rpm。

验证：159项固件测试、42项电脑端测试通过；板端假总线验证一分钟各1mL及心跳停机；实际MicroPython标准输入轮询在无后续请求时触发超时停机（假总线，不访问电机UART）；真实短轴仅验证静止时的刹车/解除通信，前后编码器不变。模拟HTTP启动、体积显示、停止、断开通过。**未进行真实连续推注或实际流量校准，未完成浏览器视觉/实际点击验收。**部署前备份在 `backups/before_syringe_feed_20261110_150343/`。

## 急停与三轴复位（2026-11-10）

**急停三轴：** 顶部红色按钮对当前控制服务可用，查看页也可触发。信号直接通过USB Ctrl+C中断板端控制循环，不等待定位或连续复位完成。板端首先广播刹车，再广播失能，随后逐轴确认失能应答与编码器静止；不发送清除刹车或重新使能指令。全部通过后界面才显示“急停已确认”。故障或无反馈时显示“未确认”，需要切断电机电源。急停是软件功能，依赖电脑、USB、ESP32和RS485，不是独立硬件急停。

急停会清除位置基准、取消任务、断开设备并禁止自动重连；锁存保存在 `webcontrol/runtime/emergency-latch.json`，服务重启不会自动解除。版本9起，排除故障后勾选确认，点击“恢复驱动并解除急停”，由服务验证恢复驱动状态，再核对位置建立基准。恢复不下发运动指令。无反馈时必须先实际确认停机，不能把界面解除当作停机证明。

**三轴连续复位：** 在新面板分别填写三个目标位置（mm），速度默认 **30rpm**，可选3–30rpm；确认三轴目标和运动路径后点击“三轴连续复位”。这是回到指定坐标，不是撞限位找零。三轴需均有本次标定，目标须在各自安全区内；任一轴无效会拒绝整项任务。已到目标的轴不移动，其余轴各发送一次完整有限位移指令，连续回程并各自到位停止，不再逐段停顿。30rpm、4mm导程对应名义线速度约2mm/s。ESP32持续读取编码器，检查方向、范围、停滞和到位；主机心跳超过1.5秒未到则刹停。停止或异常后需重新建立位置基准。急停后不会自动复位或续跑。

验证：161项固件与50项电脑端测试通过；模拟HTTP确认30rpm复位及急停/解除流程。实际MicroPython假总线中断长运动等待，从发送急停到确认约0.473秒；真实三轴**静止状态**急停确认约0.548秒，均为本次观测而非保证时限。未进行带载运动急停或30rpm复位的实机验收。新固件逐文件SHA256校验，更新前备份 `backups/before_emergency_reset_20261110_152710/`；前两次上传超时均未替换板上旧模块。

## 调节位置与速度

- **目标定位**：输入该轴绝对目标坐标，点击“移动”。例如当前尺量基准为 51 mm，
  远离原点 50 mm 对应目标 **101 mm**。页面“＋前进”为远离零点，“−后退”为靠近零点。
- **单步调节**：选择 0.1、0.5 或 1 mm，点击前进或后退；每次点击只提交一次。
- **速度**：输入或拖动至 3–30 rpm 的整数，默认 12 rpm；设置作用于下一次运动，运动中不能更改。
  本机导程约 4 mm/圈，12 rpm 对应名义线速度约 0.8 mm/s。分段反馈检查会增加总用时。
- **运动进度**：每个任务只选一轴，较长距离分成最多 1 mm 的有限小段；上一段完成并核对反馈后才发送下一段。
  单轴操作时其他轴保持不动；并行任务同时推进所选轴。运动期间其他操作锁定，可随时请求停止后续动作。

端点定位为反馈容差留有约 0.1 mm 的内缩，并允许小尾差，界面数字不是新的尺量精度保证。
实际物理余量仍依赖正确基准、导程和方向。当前已实机验证从 6 提高至 **12 rpm**；
允许设置的 30 rpm 上限尚未经过实机逐速验证。

## 停止、断线与控制权

“停止”请求板端制动并验证静止，确认后保留基准、允许提交新任务。紧急情况使用红色“急停三轴”；未确认停止时切断驱动电源。软件停止依赖通信，不是独立硬件急停。

同一时刻只有一个页面可取得控制权；其他页面只读，但可以请求停止。前端每秒发送心跳，
控制服务在心跳失效后取消后续运动并锁定。刷新、重连或请求结果不明确时不自动重发运动，
也不会续跑旧任务。先查看状态与日志，确认设备已停止，再建立新基准。

## 常见情况

| 显示或现象 | 处理 |
|---|---|
| 控制服务未连接 | 重新运行 `./start-control.sh`；查看 `webcontrol/runtime/server-8765.log` |
| 未发现 ESP32 | 核对 USB 数据线、开发板连接和电机独立电源；点击“连接设备” |
| 串口被占用 | 停止原程序，在 Thonny 中“运行 → 断开”；关闭其他串口采集程序 |
| 页面只读 | 使用原控制页；原页退出、控制权释放后，点击“获取控制权” |

## USB 光谱仪网页功能（2026-11-11）

**当前持久化规则（覆盖下文早期的“重连重采”说明）：** 同一台光谱仪完成一次暗场和波长标定后自动保存；重启/重连自动恢复ROI、曝光、处理设置及匹配的底噪，波长标定也自动加载，无需重复选峰。文件位于 `spectrometer/runtime/web/instrument-profile.json` 与 `calibration.json`，前者更新时保留一份 `.previous.json` 备份。

改变ROI/曝光后旧底噪只暂停使用、不删除；“恢复校准时设置”可恢复该次暗场的采集条件并继续使用。平均帧数、平滑、峰值保持不改变暗场原始强度算法，因此不会要求重采；零参考仍为临时状态。显式“清除已存暗场”会清除默认配置中的暗场（波长标定不变）；采集未完成时取消或断开，保留上次成功保存的暗场。设置不匹配、文件损坏或相机参数无法恢复时不套用底噪，并显示原因。若改变光路、设备或长期温漂导致校准失准，需重新校准。

运行 `./start-spectrometer.sh`，打开独立页面 `http://127.0.0.1:8766/`。光谱仪与 ESP32 分别连接：不必取得电机控制权或连接 ESP32，即可采集光谱。网页关闭后相机采集/连续记录仍在本机服务中进行；结束实验请点击“结束记录”和“断开光谱仪”。光谱仪断开不影响电机任务，电机急停也不关闭光谱记录。

1. 点击“扫描光谱仪”，选择匹配的 USB-ZH 采集接口，再点击“连接光谱仪”。扫描不自动打开采集流；连接后请核对原始预览是否有真正的狭缝光谱带。
2. 使用原图像素填写 ROI 的 x/y/宽/高，或自动寻找亮带；预览的绿色框显示当前 ROI。自动找亮带不能判断真实光谱。
3. 调整曝光（当前相机 100 µs 单位）、1–100 帧平均、平滑、峰值保持。改 ROI、曝光或处理设置会清除平均缓存及零参考。零参考仅做逐像素相减，不是吸光度。
4. 展开“波长标定”，输入至少三组 `绝对像素:已知波长nm`，逗号分隔；不得用演示点替代实测。标定要求全画幅拟合单调，并绑定 USB 身份及实际分辨率，保存于 `spectrometer/runtime/web/calibration.json`。未标定横轴只显示像素。旧 CLI 标定文件不会自动套用；换光路仍须人工重新标定。
5. “保存当前光谱”生成 CSV、元数据 JSON、光谱 PNG、原始帧 PNG，页面出现下载链接。“开始连续记录”按 0.2–60 秒间隔写 JSONL，点击“结束记录”后下载完整文件。文件保存在 `spectrometer/runtime/web/captures/`，文件名唯一，避免覆盖。同一服务会话中导出链接有效，服务重启后文件仍可从目录读取。

设备隔离规则：

- 光谱仪限定 VID:PID `0c68:6464`、驱动 `uvcvideo`、有效视频采集节点，排除内置摄像头和 metadata。选择携带 VID:PID、by-id、名称；打开前重新枚举校验，节点重新编号不直接沿用旧 `/dev/videoN`。相同身份出现多个候选时拒绝猜测。当前摄像头无唯一序列号，替换同型号实物后仍应重新确认光路和标定。
- ESP32 仅枚举 Espressif `303a` 或现用桥接器 `1a86:7523` 的 ttyUSB/ttyACM 节点，视频节点永不进入串口候选。多候选时停止自动选择；可在服务命令中显式指定 `--serial-port`，该路径仍须通过身份筛选和协议握手。通用 CH340 的 VID/PID 本身不是 ESP32 身份证明，最终还需 MicroPython 网页协议握手。
- 相机在独立线程中读帧及处理，使用独立进程锁；不调用电机 RPC、不抢占 ESP32 串口。读帧失败停止相机并保留错误，不自动重连或切换设备；最后一帧会标为已停止。
- 光谱请求沿用本机 Host/Origin 检查及页面令牌。导出只允许当前服务已登记的采集文件，不能请求任意路径。

接口：`GET /api/spectrometer-devices`、`GET /api/spectrometer-state`、`GET /api/spectrometer-preview`、`POST /api/spectrometer`（op 字段）、`GET /api/spectrometer-file/<已登记文件名>`。相机命令异步执行，错误与结果在 state 接口中反馈；命令被接受不等于完成。

本次真实设备已验证能采集 1280×720 MJPG 画面，但当前图像接近全黑，显示低光；尚未确认有效光谱带或波长精度。强度是相机计数，时间戳是电脑时间，无电机硬件同步。浏览器自动化宿主不可用，未完成真实浏览器视觉验收；后端与真实设备 HTTP 链路分别验收。


### 暗场校正：将完全遮光时的计数作为底噪

光谱面板新增“暗场校正 · 扣除底噪”，与“零参考”和“波长标定”相互独立。

1. **先在有光时选定实际光谱带 ROI**，固定手动曝光并点击“应用曝光”；曝光应与之后测样时一致。不要在遮光后自动寻找 ROI，否则可能选到不同位置。
2. 完全遮住入光口，勾选遮光确认，点击“采集暗场并校正”。默认32帧，可选8–256帧。程序丢弃3个新帧，再从后续独立帧逐像素求平均，不复用旧的多帧平均缓存。保持遮光直到进度完成。
3. 显示“暗场校正已启用”后打开入光口测量。校正强度 = 原始强度 − 暗场均值；若另设零参考，再减去校正后的零参考。负值保留，以免把零点附近的随机噪声截断成正偏差。原始预览、RGB和亮度列保持未扣暗场。
4. “取消 / 清除暗场”可取消尚未完成的采集或停止扣除。更改ROI、曝光或处理设置会清除暗场与零参考；每秒检测一次相机控制值，发现变化也会清除。重连后重新采集，不自动套用旧底噪。温度、光路发生变化时也应主动重采。

自动曝光不能用于暗场校正；连续JSONL记录期间须先结束记录再采暗场，避免把遮光帧混入样品序列。采集中禁止更改ROI、曝光、处理、零参考或保存测量；可取消暗场或断开。饱和画面会取消校正，但软件不能验证是否真正完全遮光，需以实际遮光操作为准。

CSV 新增 `raw_intensity`（扣除前强度）及 `dark_background`（逐像素底噪），原有 `intensity` 为扣除后强度，`display` 为后续平滑/峰值保持值。JSON/JSONL 的 `dark_correction` 包含底噪数组、采集帧数、时间、设备身份/分辨率、ROI、相机控制值、处理参数和帧间波动统计。导出光谱PNG也保留负值显示。暗场只在当前连接中启用；导出文件保留校正证据，不会在下次连接自动加载。

API：`POST /api/spectrometer`，`op=dark_start, frames=32, confirmed=true`；取消/清除为 `op=dark_clear`。状态接口的 `dark.status` 为 `none/collecting/ready`，`count/total` 给出进度，`record.stats.dark_corrected` 指明该帧是否已扣暗场。暗场校正减少平均底噪偏置，不能消除所有随机噪声，也不替代波长或绝对响应标定。


### 两步校准：暗场本底 → 皓宇灯波长

1. **第一步：暗场本底扣除。** 将完全遮光时逐像素强度的多帧均值作为固定底噪偏置，按前述暗场流程扣除。这一步校正纵轴本底，不建立波长轴，也不会消除全部随机噪声。
2. **第二步：皓宇荧光灯波长标定。** 保持同一ROI、曝光和处理设置，对准皓宇灯，确认来源后点击“冻结当前灯谱用于选峰”。冻结的是本机采集、已扣暗场的强度，实时采集仍继续；下面的冻结图固定显示原图像素。勾选某行“选这个峰”，点击相应峰顶吸附候选峰，或输入该峰原图像素。默认用436、546、610nm三个主峰拟合二次曲线；404nm可填像素并保持不勾选，作为独立验证。确认对应后点击“按对应峰拟合并保存波长标定”。

参考文件为项目 `Archive/皓宇荧光灯.png`（大写A目录），界面显示原图副本 `webcontrol/static/references/haoyu-fluorescent.png`。这是带整数标注的光谱截图，不是原始谱线表或可溯源标准。默认使用图中436、546、610nm；不擅自换成其他荧光灯资料中的精细波长。404nm是可选补充峰；487、512等宽峰仅辅助识别，未作为默认锚点。**不能把参考图片的像素直接填成当前相机像素。**

候选峰仅辅助点击，不自动判断谱线身份；必须对照参考图确认颜色、峰形和顺序。暗场未完成、零参考未清除、当前饱和/信号过弱/可辨峰少于3个时拒绝冻结；改变暗场、ROI、曝光或处理设置后旧快照失效。保存时校验快照身份、当前暗场和相机参数、峰位置、重复点、谱线顺序以及拟合的单调性，连续记录期间禁止更改标定。支持横向正序或反序的光谱。

结果显示各拟合点误差、拟合RMS、可选独立验证峰的误差和校准像素范围。三点二次拟合能恰好通过三点，R²=1不证明准确；实际覆盖范围外是外推，图片整数参考不能支持亚纳米精度。如果独立验证差异大，应重新检查选峰、光路和实际ROI。

保存记录包含参考图路径和SHA256、灯谱快照时间与ID、当次暗场ID、ROI、拟合/验证点及误差。校准文件的report与calibration.verification记录这些信息；JSON/JSONL导出也随波长标定保留verification。现有高级手工标定保留，用于其他已知光源；其流程不自动套用皓宇灯参考。

新增操作：`lamp_capture`需`confirmed=true`；`lamp_calibrate`需`snapshot_id`、`points`及可选`check_points`。状态中的`lamp`保存冻结谱与候选峰，`calibration_report`保存最后的皓宇灯标定报告。界面与模拟测试通过不代表实际光路已校准，必须完成遮光及实灯选峰。


### 灯谱拟合折返与峰位波动（2026-11-11 更新）

网页默认提供三点或四点线性拟合，仍可明确选择二次拟合。二次模型检查整个相机画幅，缩小 ROI 不会缩小其检查范围；若外推折返，拒绝保存并提示核对峰对应或选择线性模型。线性模型显示每峰残差和 RMS，单调不等于准确；残差较大时需重新核对对应，不能把拟合通过当作标定可靠。

灯谱冻结要求至少32帧平均已填满。保持曝光和光路稳定、对准灯后等待平均缓冲更新，再冻结并选择同一组谱峰；峰值保持只影响实时显示，校准用的冻结曲线不使用历史峰值保持。实时“峰位置”是全谱最大值位置，多条峰强弱交替时可能跳到另一条峰，不等于同一条谱线漂移。暗场因曝光改变暂停时，先恢复校准时设置，或重新遮光采集。

## 2026-11-11：连续运动、位置记忆和参考谱

网页的单轴定位、定距前后移动、多轴同时定位、向内恢复和三轴复位，统一使用 ESP32 监督的整段有限脉冲运动；不会按 1 mm 反复停顿。注射继续使用恒速模式。板端每 50 ms 尝试采样（受串口读取耗时影响），主机约每 0.3 s 获取反馈，网页约每 0.5 s 刷新，显示位置来自编码器换算，不以名义速度积分冒充实测位置。保留软边界、非运动轴检查、心跳、停止及急停。

`webcontrol/runtime/positions.json` 保存最后确认的机械位置、轴对应、方向、导程及 ESP32 身份。首次尺量后、正常到位后以及确认停止后自动更新。每次运动发出之前先把磁盘记录标记为“运动中，不可恢复”，避免中途掉电后恢复过时位置。正常重连后点击 **恢复已保存位置**，只读取编码器并重建基准，不发送运动命令。这个恢复方式依据丝杆无法手动移动的条件；拆装、急停、通信异常或未确认停稳后重新核对。没有自动续跑。

服务重启后，首次连接同一台 ESP32 时自动用可信记录重建位置基准。需要更改时，打开「设备与标定」并填写实测位置。急停时，对能读到静止编码器且已有位置基准的轴，保存急停后的坐标作为下次尺量校准的参考。若没有可信停稳读数，界面只显示此前记录并标明来源。急停记录不可用“恢复已保存位置”直接建基准。位置校准只需确认本次尺量值；方向和导程沿用对应设备和轴的上次设置，首次默认为反转（−1）及 4 mm/圈，可以在校准卡片的“方向与导程”中修改。

光谱仪数据保存在 `spectrometer/runtime/web/`：

- `instrument-profile.json`：暗场底噪和相机设置。
- `calibration.json`：荧光灯波长拟合、选峰点、误差报告；新版保存时也包含冻结灯谱。旧版的拟合文件仍直接兼容，旧版未写入的冻结图像不能补造。
- `halogen-reference.json`：空白光路、无样品的卤素灯 I₀，含逐像素暗场扣除强度、采集条件及参考编号。首次需在网页确认空白光路后采集，不能用当前未知光源自动代替。
- `captures/`：单次 CSV / JSON / PNG 与连续记录 JSONL。网页“全部历史记录与校准文件下载”重启后仍列出文件；大 JSONL 以分块方式下载，避免一次读入内存。

样品和 I₀ 采用暗场扣除后的强度，不采用峰值保持曲线。匹配设备、ROI、曝光控制、增益及暗场编号后，计算透过率 `T=I/I₀` 和吸光度 `A=-log10(T)`。弱参考、饱和、非正样品值不计算，CSV 留空，JSON 为 null；不把 T>1 强行裁剪。透过损失 `1-T` 包含反射、散射等，不能直接作为材料吸收率。波长标定误差会影响横坐标，应检查保存的拟合残差。


## 自动光谱范围与固定曝光（2026-11-11）

网页采集固定手动曝光：连接恢复已保存曝光值，不再提供自动曝光开关。手动改变曝光后，只有相匹配的暗场及空白 I₀才能使用。外部程序改变相机控制参数时暂停旧暗场；若被改成自动曝光，服务会重新固定手动曝光，并提示恢复校准设置。

网页不再填写 ROI 坐标。首次连接尚未保存范围时，平均8帧，根据背景与噪声阈值寻找所有有空间支撑的光信号，取其包围范围并保留2像素边缘；不会只按最强峰的固定百分比裁掉弱红光/蓝光。孤立热像素不用于确定范围，无可识别信号时继续等待，不保存猜测范围。

首次用完整的卤素灯光谱识别范围，识别后固定并保存；随后遮光采集暗场、校准荧光灯波长、保存空白卤素灯 I₀。样品吸收或全黑不会让 ROI 自行缩小。重连沿用已保存的范围和匹配暗场；仅在光路变化时点击“重新识别光谱范围”。若实际识别范围变化，暂停不匹配的暗场与 I₀，原文件保留，可恢复原校准设置；波长拟合文件仍保留，光学结构改变后需检查波长对应。
