二、当前项目结构与运行方法

源码以 firmware/ 为准：
```text
  firmware/main.py                      上电自动启动，3秒Ctrl+C窗口
  firmware/lib/enzyflow/config.py       接线、增益、采样、校准和检测参数
  firmware/lib/enzyflow/acquisition.py  AS7341硬件采集
  firmware/lib/enzyflow/processing.py   遮挡逻辑及RGB估算
  firmware/lib/enzyflow/protocol.py     JSON Lines输出
  firmware/lib/enzyflow/app.py          主应用
  firmware/lib/as7341.py                配套驱动，增加测量超时
  firmware/lib/as7341_smux_select.py    通道配置
  firmware/lib/as7341_led.py            LED控制库
  firmware/lib/light_monitor.py         兼容旧导入入口
```
lib -> firmware/lib，为本地快捷符号链接。
原本地代码保存在 archive/lib_before_reorganize/。
详细运行说明在 README.txt。

采样设置：ATIME=29，ASTEP=599，增益8倍。
自动校准10帧，以Clear中位数为基准；每帧为两组依次采集，校准需要数秒。
启动时保持无遮挡；过暗或饱和时报告错误，返回REPL。
可在config.BASELINE中指定已测得的无遮挡基准，避免每次启动自动校准。
Ctrl+C停止，重新运行：
```text
  from enzyflow.app import run
  run()
```
运行遮挡检测时不要另行开启LED。

数据：每行一个JSON对象，schema=1，source=esp32.as7341。
公共字段：device_id、seq、t_ms、event。
measurement包含state、signal、channels(F1~F8)、clear、nir、saturated、rgb_approx。
ready包含校准基准、阈值及采样参数。
t_ms是会回绕的开发板计时，不是UTC时间；两台设备对齐需电脑记录接收时间。

维护工具：
```text
  tools/board_tool.py：backup、deploy、exec；使用Thonny的Python运行。
  tools/test_processing.py：防抖、迟滞和RGB边界测试。
  tools/validate_board.py：一次性部署迁移及板上验证脚本。
```
board_tool目前假设/dev/ttyACM0和恰好一个Thonny ESP后端。
它会中断正在运行的应用、短暂暂停后端访问串口，再恢复后端。
后续操作先检查实时端口和进程，不要依赖本次使用过的进程号8032。
不要让电脑采集程序与Thonny同时占用同一串口。
